# AUREVIA COPILOT V2.3.80 — Moteur universel de calcul contractuel

- Suppression de la page dédiée au broker et de l’enregistrement d’un profil broker permanent.
- Saisie des paramètres du broker et de l’instrument directement lors de chaque prise de position.
- Un moteur commun traite les positions manuelles et les positions créées après confirmation d’analyse via Telegram.
- Trois méthodes adaptées aux spécifications du broker : taille du contrat, valeur du point et valeur du tick.
- Validation du broker, de la devise du compte, du lot minimum, du pas, du maximum, des frais et des paramètres propres à la méthode choisie.
- Le levier et la marge par lot sont conservés dans le snapshot ; aucune marge n’est inventée si la donnée broker manque.
- Chaque groupe et chaque position cloud conservent un snapshot JSON des paramètres contractuels et du compte.
- Le worker serveur TP/SL utilise le même moteur de calcul que l’application ; une spécification manquante ou invalide bloque la clôture calculée au lieu de fabriquer un P/L.
- Telegram : `/lot CODE unique 0.05` ou `/lot CODE separate 0.05`, puis `/spec CODE MODE LOT {JSON}` avec les spécifications exactes. Aucune position n’est créée avant validation du second message.
- Aucun broker externe, MT5 ni ordre réel n’est connecté ou exécuté.
- Migration Supabase `20261113142328_universal_contract_snapshot_v2380` appliquée et vérifiée ; la fonction RPC étendue reste exécutable uniquement par `service_role`.

## Vérification

- 247 tests automatisés réussis.
- Les tests couvrent les méthodes contrat/point/tick, les calculs BUY/SELL, les frais, les conversions, le risque, les snapshots et le parcours Telegram.
- Les tests automatisés ne remplacent pas une validation terrain sur des comptes de démonstration et les spécifications réelles des brokers.
